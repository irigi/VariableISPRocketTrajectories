# Adaptive PMP Extremal Atlas

`pmp_extremal_atlas.py` is a drop-in replacement for the earlier fixed-count
forward-atlas generator.

## What changed

The old generator stopped after `n_samples` launch attempts. The adaptive
version treats `n_samples` as a **maximum launch-attempt budget** and stops early
only when independent feasible holdouts are recovered at the configured
success rate.

For each coverage round it:

1. Integrates a fresh Sobol batch that was not used as atlas seeds.
2. Selects spatially diverse endpoint/branch representatives.
3. Attempts the same exact shooting correction used by normal queries.
4. Counts a probe as covered only when correction converges without its own
   launch being present in the atlas.
5. Inserts representative failed probes as new exact seeds.
6. Stops after the target success rate is reached for several consecutive
   rounds.

The holdouts are forward extremals, so they are known to be feasible. The
criterion measures coverage of the feasible endpoint image generated by the
configured launch domain; it does not assert that every point in the enclosing
rectangular endpoint bounds is feasible.

## Redundancy removal

Initial rows are coarsely thinned by endpoint cell and obvious branch labels.
Final pruning is conservative: a row is deleted only when its exact endpoint is
successfully recovered from other active seeds. This tests convergence rather
than deleting points based only on geometric proximity.

## Per-seed empirical cells

The NPZ contains:

- `coverage_radius`
- `coverage_success_count`
- `coverage_failure_count`

The radius is estimated in endpoint coordinates divided by `feature_scale`.
It records the portion of the last independent validation set that converged to
that seed. It is an empirical certificate, not a proof outside the tested
sample.

## Generate

```bash
python pmp_extremal_atlas.py generate adaptive_extremals.npz \
  --config atlas_config_adaptive_general.json
```

Generation prints one line per coverage round. If the launch budget ends first,
the atlas is still saved, but metadata contains:

```json
"coverage_converged": false
```

## Inspect

```bash
python pmp_extremal_atlas.py inspect adaptive_extremals.npz
```

Important metadata fields include:

- `coverage_converged`
- `coverage_final_success_rate`
- `coverage_history`
- `integrated_launch_attempts`
- `verified_pruned_rows`

## Independent validation

Run a fresh holdout test after generation:

```bash
python pmp_extremal_atlas.py validate adaptive_extremals.npz \
  --launches 8192 --rows 1024 --workers 8
```

Use a different `--seed` for repeated validation runs.

## Query

The public API is unchanged:

```python
atlas = ExtremalAtlas("adaptive_extremals.npz")
solution = atlas.solve(initial, final, rocket, revolutions=0)
```

A failed query now reports both nearest normalized distance and the nearest
seed's empirically validated cell radius.

## Important configuration point

For a genuinely general seven-dimensional atlas, do not restrict
`u0_bounds` and `w0_bounds` to nearly circular values. The included general
configuration uses broad initial-velocity bounds. A circular-start-only atlas
should be generated as a separate shard rather than replacing the general
atlas.
